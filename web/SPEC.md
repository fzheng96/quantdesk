# QuantDesk Web SPEC (lives in web/ inside the quantdesk repo)

A zero-config browser app: it tells the user what trades a systematic strategy would make today, lets them follow the plan into a local paper portfolio with one click, and proves its methodology with an in-browser backtest of the exact engine making the recommendations. Next.js 14+ app router, TypeScript strict, no UI framework beyond React + hand-rolled CSS (reuse the tearsheet palette: bg #0e1117, panels #171c26, borders #262d3b, cards #1d2330, text #e7eaf0/#8b93a7, accent #5ab0f2). Repo-local web/.npmrc with registry=https://registry.npmjs.org.

## lib/engine/ (TypeScript port of the Python engine — parity is the contract)
- Port from ../quantdesk/*.py (read them): strategies tsmom, xsmom, dma (skip meanrev in the product; port it only for parity tests), the backtest engine (one-day weight shift, turnover costs: commission 1bp + slippage 2bps), metrics (cagr, annVol, sharpe, sortino, maxDrawdown, calmar, hitRate), risk overlays (volTarget, capWeights at 0.25).
- Data model: prices as { dates: string[], tickers: string[], closes: number[][] } (row-major by date). Pure functions, no DOM.
- THE BLEND (the product recommendation engine, define once in lib/engine/blend.ts): average the target weights of tsmom, xsmom, and dma equally, then volTarget the blend to the user risk setting (conservative 8% / balanced 12% / aggressive 16% annualized), then capWeights 0.25. Document in code why meanrev is excluded (worst Sharpe and deepest drawdown of the four on the 2018+ universe — cite the numbers).
- PARITY TESTS: web/test/fixtures/parity.json comes from the Python engine via scripts/make_parity_fixtures.py. It contains a seeded synthetic price panel plus, for each strategy and the blend pipeline, the Python-computed weights, net returns, equity curve, and metrics. Vitest must reproduce every series within 1e-8 relative tolerance. This is the proof the browser engine IS the audited engine.

## app/api/prices/route.ts (the only server code)
- GET /api/prices?tickers=AAPL,MSFT&years=5 -> { source: "yahoo"|"stooq", asOf: ISO string, dates, tickers, closes } fetched server-side: Yahoo v8 chart API first (adjclose preferred; UA header "Mozilla/5.0 (compatible; quantdesk/0.2)"), Stooq CSV fallback, mirroring the Python data layer semantics. Validate tickers against the DEFAULT_UNIVERSE allowlist (reject others, 400) — this is a proxy, not an open relay. Response headers: s-maxage=3600, stale-while-revalidate=86400.
- DEFAULT_UNIVERSE: the same 20 megacaps as the CLI plus SPY benchmark.
- If both sources fail server-side, return 503 with a clear error body; the client then offers bundled demo data (web/public/demo-prices.json, built from the real local price cache, labeled with its as-of date).

## Live sync (the app tracks real-world prices at all times)
- app/api/quote/route.ts: GET /api/quote?tickers=AAPL,SPY -> { asOf: ISO string, marketState: "open"|"closed"|"pre"|"after", quotes: { ticker: { price, prevClose, changePct } } } fetched server-side from Yahoo v8 chart with range=1d (last traded price; fall back to prevClose when no session data). Same DEFAULT_UNIVERSE allowlist and 400 on others. Cache-Control: s-maxage=60, stale-while-revalidate=300. Derive marketState from the Yahoo meta when present, else from NYSE hours in America/New_York.
- web/lib/use-live-quotes.ts: client hook useLiveQuotes(tickers): fetches on mount, re-fetches every 60 seconds while document.visibilityState is "visible", and immediately on visibilitychange/focus. Exposes { quotes, asOf, marketState, isStale } where isStale = last successful refresh older than 5 minutes.
- Everything the user sees is marked to the latest quote: order dollar amounts and share quantities on the Today plan, portfolio value, per-position values and P&L, and the current endpoint of every equity chart.
- A persistent header badge on every page: "Prices as of H:MM ET - market open/closed", turning amber with the word "stale" when isStale. Tapping it explains the honest model in one sentence: recommendations are computed once per day from daily closing prices; live quotes (which the source may delay up to about 15 minutes) keep valuations and order sizing current between closes.

## State (lib/store.ts)
- localStorage only, single namespaced key "quantdesk.v1". Shape: { settings: { budget: number, risk: "conservative"|"balanced"|"aggressive", createdAt }, portfolio: { cash, positions: {ticker: shares}, trades: [{date, ticker, side, shares, price}], snapshots: [{date, value}] } }.
- Pure reducer functions with unit tests: applyPlan(orders, prices), markToMarket(prices), reset. Money math in cents internally to avoid float drift in displayed cash.

## Pages
- / (Today): If no settings: the 2-question setup (paper budget default $100,000 with a note it is pretend money; risk dial with three plain-language options, e.g. balanced = "aims for roughly two-thirds of the stock market's bumpiness" (fractions anchored to the market's historical 16-20% annualized vol)). Then: TODAY'S PLAN — the blend's current target portfolio vs the user's paper positions, rendered as a concrete order list ("Buy 17 shares of AAPL — about $5,000") with a one-click "Follow today's plan" that applies all orders at the latest quoted prices (most recent close when no quote is available). Below: portfolio value card, vs-SPY sparkline, next-rebalance note (signals update daily after market close; trading more than ~weekly mostly pays costs — say so). Every metric card has a hover/tap "?" with the plain-English meaning.
- /portfolio: positions table (shares, value, weight, since-buy P&L), trade history, equity chart vs "just bought SPY" from the SAME start date, honest framing of differences. Reset button with confirm.
- /why: the trust page. Runs the EXACT blend engine over the fetched 5-year history IN THE BROWSER (visible "computing..." then results): equity curve vs SPY, drawdown chart, metric cards, a "what could go wrong" section (regime change, costs, crowding, the 2022-style year for momentum), and the parity statement (this engine matches the audited Python engine to 8 decimals — link to repo tests). State the backtest window honestly and that the 2018+ megacap universe carries survivorship flavor.
- /learn: adapt the existing site/guide.html content (read it) to the browser app: how to read every screen, a guided 5-minute first session (setup -> read the plan -> follow it -> check back tomorrow), glossary. CLI content moves to a short "power users" footnote linking the repo.
- First-visit overlay on /: 3-step walkthrough (1. this recommends simulated trades, 2. follow the plan with one click, 3. check /why to see the evidence) — dismissible, never returns (localStorage flag).
